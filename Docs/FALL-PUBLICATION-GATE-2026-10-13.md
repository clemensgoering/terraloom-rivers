# Physical fall publication gate (13 October 2026)

An explicit, single-site fall on one already bound Core-owned Terrain tile now moves from `FallCandidateOnly` to a complete plan only after `PreparedFallEarthworks` has prepared and checked its terrain hole, closed rock solid, collider contact, upper/fall/lower water meshes, pool and outlet. The published plan carries a hard protected footprint. The ordinary river route and format-2 JSON path remain unchanged; an owned fall uses format 3. A fall on supplied terrain, a prepared external source or a multi-tile/brush site is still rejected with a diagnostic.

`TerraLoomRivers.PrepareFromSnapshot` stages terrain, collider-backed rock, water, plan and JSON without changing the live world. `PreparedPublication` validates the old bindings immediately before swapping them. Disposal before completion restores the previous terrain, collider, root, plan and JSON. `LoadPlanJson` validates against the staged complete plan before binding anything. The Rivers inspector exposes fall rock and optional fall-water materials; baking accepts a published fall without irrelevant bed/bank materials and persists the fall materials.

Evidence: `Temp/FallPublication-20261013-c.xml` (Unity 6000.3.9f1 EditMode, 1/1) exercises complete publication, protected reservation, mesh/collider and TerrainData binding, aborted staging, stale live binding, invalid JSON, valid JSON reload, cancellation, repeat generation and Clear. `Tools/RiverPlannerTests.csproj` passes 21/21 portable checks; `Tools/verify.py --compile --development-core ../Core` passes without warnings/errors. Earlier earthworks native test: `Temp/FallEarthworksGate-20261013.xml` (1/1).

This is a bounded physical site release, not general waterfall readiness. Save/reopen of a baked fall and same-camera Player visual/contact acceptance remain open. Automatic fall discovery, foreign terrain and multi-tile falls remain unsupported. A single route-bound fall cannot currently be composed with other river routes in the same request batch.

Buyer UX follow-up: the in-progress Core Workbench now presents a World entry tab, discovered generation order, one `Generate world` button, module management and tabs.
